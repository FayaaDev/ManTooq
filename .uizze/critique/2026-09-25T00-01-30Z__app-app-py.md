## Priority issues

1. **P1 — Failed retry removes existing playback** (`app/app.py:107-128`). `pop("audio")` precedes validation and the API call, so failure empties the player. Keep the previous audio until replacement succeeds; show failure beside it. `/uizze harden`.
2. **P1 — First library-voice use depends on an unexplained ID** (`app/app.py:77-100`). With no saved clone the default library path gives no way to find the identifier. Add adjacent guidance and a direct route to cloning when needed. `/uizze onboard`.
3. **P2 — Generation readiness is fragmented** (`app/app.py:63-72, 94-119`). Key entry is in the header while voice and text are in the editor; users may submit without knowing what is missing. Provide a concise in-context readiness cue and next action without displaying the key; explain the online usage implication. `/uizze clarify`.
4. **P2 — History is difficult to identify** (`app/app.py:153-168`). Numbered recordings and a seed tooltip do not identify a previous take. Show available date/time or other saved context; this is source-inferred, not visually inspected. `/uizze harden`.
5. **P2 — Cloning uploader breaks Arabic continuity** (`app/app.py:134-138`). At 390 px the native control visibly says “Upload” and “200MB per file”. Use supported localization if available or adjacent Arabic format/size guidance. `/uizze clarify`.
